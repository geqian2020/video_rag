# Kiro 会议视频转录工作流

请创建一个工作流，递归扫描当前项目目录及其所有子目录，查找 `.mp4` 文件，并将其中的中文音频转录为 Markdown 文本。

## 工作要求

* 递归扫描当前项目目录下的所有文件夹。
* 仅处理 `.mp4` 文件，忽略其他格式。
* 从视频中提取音频后进行中文语音转录。
* 每个视频生成一个同名 Markdown 文件。
* Markdown 文件与原始 MP4 文件保存在同一目录。
* 如果同名 Markdown 文件已存在，跳过该文件，避免重复处理。
* 支持文件名包含中文、空格和特殊字符。
* 单个文件处理失败时记录错误并继续处理其他文件。
* 最后输出处理统计，包括：
  * 找到的 MP4 文件数量
  * 成功转录数量
  * 跳过数量
  * 失败数量
  * 失败文件及原因

## Markdown 输出格式

每个视频生成的 Markdown 文件使用以下结构：

```markdown
# 会议转录：{视频文件名}

* 原始文件：`{视频相对路径}`
* 转录语言：中文
* 生成时间：{生成时间}

## 转录内容

{带时间戳的完整转录文本}
```

时间戳格式使用 `[HH:MM:SS]`。如果语音无法识别，保留最接近的时间位置并标记为 `[无法识别]`。

## 技术实现建议

* 使用 `ffmpeg` 从 MP4 中提取音频。
* 使用本地或已配置的中文语音识别模型进行转录，例如 Whisper。
* 优先使用 GPU；没有 GPU 时自动回退到 CPU。
* 音频转换为适合转录的格式，例如单声道 WAV。
* 临时音频文件应在处理完成后自动删除。
* 转录过程应支持较长会议视频，并避免一次性将整个音频加载到内存中。
* 对路径进行安全处理，避免覆盖原始 MP4 文件。
* 提供清晰的命令行入口，例如：

```bash
python transcribe_meetings.py
```

## 验收标准

* 从项目根目录运行命令后，能够递归发现所有 MP4 文件。
* 每个成功处理的视频旁边生成一个同名 `.md` 文件。
* 生成的内容为中文转录，并包含时间戳。
* 已存在对应 Markdown 文件的视频默认不会重复处理。
* 一个文件失败不会中断整个批处理流程。
* 程序结束时显示完整统计信息。
